# CHAPTER 5: IMPLEMENTATION AND TECHNOLOGIES

## 5.1 Technical Environment and Platform Implementation
The implementation phase of the AISHA project was characterized by a commitment to a modern, cloud native technology stack that prioritizes scalability, security, and developer productivity. We utilized TypeScript across the entire application to ensure absolute type safety from our PostgreSQL database schemas to our React component props, effectively eliminating common runtime errors during the development phase. Our frontend is built upon the React framework and the Chakra UI design system, providing a highly responsive and accessible user experience that functions seamlessly across both mobile and desktop devices. The backend infrastructure is powered by Node.js and the Express framework, hosted on high availability cloud platforms such as Render and Vercel, ensuring that the system remains responsive even as the student population at Masinde Muliro University grows.

## 5.2 Deep Dive into the AI Matching Engine and the 24 Hour Logic
The most technically advanced component of AISHA is the intelligent matching engine, which relies on a sophisticated implementation of the Google Gemini API. This implementation is driven by a complex Prompt Engineering pipeline that converts raw student data into structured professional insights. Unlike traditional systems that return a list of options, AISHA is designed to return a single "Best Fit" placement for every student. This is achieved by having the AI perform a high-depth semantic analysis that compares the student's entire academic profile against a real-time database of industrial requirements. This "Single Choice" model is intended to provide a decisive and friction-free path to industrial placement, reducing the administrative overhead for both the student and the institution.

To provide the student with a necessary level of agency, we implemented a 24 Hour Preference Window within the matching lifecycle. Once the AI presents the best fit placement, the student has exactly 24 hours to review the company, the department, and the specific requirements. If the student feels that the match does not align with their career goals, they can use this window to adjust their specialization preferences or update their skills, which triggers a new AI analysis. If no changes are made within the 24 hour period, the system considers the placement accepted and automatically initiates the next phase of the workflow, which includes the autogeneration of institutional letters and company notifications.

## 5.3 The Mathematical Logic of the Matching Algorithm
To provide transparency into how AISHA determines the absolute best fit for a student, we developed a Weighted Semantic Relevancy Score (WSRS). This algorithm does not simply look for matching words but evaluates the student across four distinct technical dimensions. Each dimension is assigned a specific "Weighting Factor" (W) based on its importance to the overall professional fit. The first dimension is Skill Alignment (W=0.40), which evaluates the student's technical competencies. The second is Course Relevancy (W=0.30), which looks at the specific academic units the student has completed. The third is Personal Interest Alignment (W=0.20), and the final dimension is Academic Performance (W=0.10).

To illustrate the calculation, consider a hypothetical student, John Doe, applying for a Software Engineering placement at Datum Limited. The algorithm follows five rigorous steps. Step one involves the Semantic Vector Generation, where the student's skills (e.g., React, Node.js) are converted into a 768-dimension vector. Step two is the Calculation of the Skill Match (S). In John's case, his skill set aligns 90% with the company's requirements, giving him a score of 90. Step three is the Course Relevancy Check (C). John has completed "Advanced Web Design" and "Database Systems," which the AI identifies as a 95% match for the role. Step four is the Interest Sync (I), where John's stated interest in "Cloud Computing" aligns 80% with the company's cloud based stack. Finally, Step five is the Academic Weighting (A), where John's high marks in relevant units provide a score of 85.

The final WSRS calculation for John Doe is performed as follows: (90 * 0.40) + (95 * 0.30) + (80 * 0.20) + (85 * 0.10). This results in a final score of 36 + 28.5 + 16 + 8.5, totaling a Composite Match Score of 89.0%. By identifying the student with the highest WSRS for a specific opening, AISHA ensures that only the most qualified candidate is presented for the placement, thereby maintaining a high standard of professional intake for our industrial partners.

## 5.4 Document Automation: Acceptance and Assignment Letters
A critical component of our administrative automation is the instantaneous generation of professional correspondence, specifically focusing on Acceptance Letters and Assignment Documents. We implemented a high-speed document generation service that creates customized PDF letters the moment a placement is finalized after the 24 hour window. These letters include the company's specific requirements, the student’s start date, and the institutional signature hashes, providing a verifiable record of the placement. This automation removes the need for students to manually draft and physically transport letters for signatures, significantly accelerating the "School to Work" transition. By focusing on these essential institutional documents, we have eliminated the administrative bottlenecks that previously delayed students from starting their industrial training.

## 5.5 Communication Infrastructure and Gmail API via OAuth2
Departing from the unreliable and insecure SMTP methods used by traditional university portals, we implemented a modern communication service using the Gmail API through the Google Cloud Console. This was a complex undertaking that required setting up a dedicated project in the Google Cloud ecosystem, configuring an OAuth 2.0 consent screen, and managing persistent refresh tokens to allow the AISHA server to send emails on behalf of the institution securely. By using the official Gmail API instead of standard mail servers, we ensured that every critical notification—whether it was an acceptance letter for a student or a placement notification for a company—always lands in the user’s primary inbox and is never flagged as spam. This reliability is essential for a platform where a missed email can lead to a significant delay in a student’s attachment start date.

## 5.6 Comprehensive Technology Stack Overview
The AISHA platform is built upon a curated selection of state of the art technologies that ensure high performance and industrial grade reliability. In addition to the core React and Node.js foundation, we integrated the Google Gemini 1.5 Flash model to provide the semantic intelligence required for our matching engine. For data persistence, we utilized Supabase, which provides a managed PostgreSQL database and professional grade S3 object storage for student assets. Financial transactions are handled through a custom integration with the Safaricom Daraja API for M Pesa STK Pushes, while our real time notification layer leverages both the Gmail API and Socket.io for instant WebSocket alerts. To manage asynchronous tasks such as bulk PDF generation, we implemented a Redis backed queue system using Bull. This combination of cloud native services and modern software design patterns ensures that AISHA is not just a student portal, but a robust and scalable institutional asset.
